# Site behavior and ownership

AWS for Engineers is a public, ad-supported blog. Every page is built into HTML ahead of time. Visitors need no application server, database, or login. The homepage lists recent posts and filters that list in the browser; the blog archive paginates all posts. Each article has a stable `/blog/<slug>/` URL, title, description, canonical URL, social image, publication date, and BlogPosting structured data. The site generates a sitemap and robots file. Unknown URLs must return HTTP 404.

Readers can browse the complete collection through numbered archive links or curated topic guides at `/topics/`. Each archive page has a distinct title and description based on its page number and contents, and retains its own canonical URL. The topic index and homepage link every topic; each guide introduces a reading path and groups related articles by reader task. All articles belong to at least one topic and link back to their relevant guides. Topic membership, section order, and starting articles are maintained together in `src/_data/topics.json` so the guides and article links agree. Topic pages are ordinary generated HTML included in the sitemap, with no client-side navigation dependency.

Article bodies use H2 for top-level sections and H3 for their subsections below the page H1. Useful contents navigation is derived from the rendered H2 headings and stays compact in a native disclosure control. Existing heading IDs are preserved; missing IDs receive stable unique section anchors. Only heading tags are changed when assigning anchors, because reserializing imported bodies could alter code examples. This organization improves navigation without changing article text or merging existing URLs.

Guille Ojeda is the author of every article. A shared Person identity drives linked article bylines, the author summary, the homepage biography and article structured data. The homepage keeps a centered Simple AWS newsletter section and a labelled link to `guilleojeda.com` beside “About Guille.” The canonical author profile at `/authors/guille-ojeda/` links to the newsletter, personal website and LinkedIn; ProfilePage markup describes the same person. AWS for Engineers is the publication's publisher, identified visibly and in structured data. The guides are developed with AI assistance, with Guille responsible for the published content.

Original publication dates are preserved. An explicit editorial modification date and a visible update note describe an actual change; the same date is used in BlogPosting `dateModified` and sitemap `lastmod`. Undated updates must not acquire freshness from import, filesystem, build or deployment timestamps. An authorship change or course-only addition is an editorial update, not evidence of technical re-review; course additions retain the previous technical update's date and context in the note. New posts omit modification data until there is a real update. A modification requires a note and may not precede publication.

The repository owns the content and media. Existing articles were migrated from their public rendered pages into HTML files after the supplied Unicorn export proved to contain no post content. HTML preserves their code, tables, headings, links, and image alt text; trying to parse those bodies as Markdown altered code in 11 articles. New posts are Markdown files with front matter and publish automatically when pushed to `main`. Imported images are local; the delivered pages must not request Unicorn Platform or SEO Bot assets or runtime scripts.

Eleventy optimizes ordinary image tags during the static build, including imported HTML and new Markdown. It emits responsive WebP images with the original format as a fallback, accurate dimensions, and lazy loading by default. Listing templates provide sizes matching their responsive grids; the first homepage/archive image loads eagerly with high priority because it can be the largest visible element. Original media remains available for social previews and existing direct links. The picture wrappers preserve the existing layout. Sora's licensed variable fonts are served locally, with only the Latin subset preloaded and local fallback metrics matched to reduce text movement during font loading. There is no runtime image service or external Google Fonts stylesheet dependency.

Production pages load the existing Google Analytics and AdSense configurations. Local and preview pages omit these requests to avoid polluting analytics and ad-network traffic. The root `ads.txt` file declares the AdSense publisher. The homepage's newsletter link keeps its existing destination and UTM parameters; newsletter subscription and personal-site content remain hosted on their respective sites. Ad fill depends on the ad network; production verification confirms script and ad requests, not a guaranteed creative on every view.

The shared stylesheet is embedded in each generated page after the local Sora preload, so rendering does not wait for a separate stylesheet request. This repeats the CSS in each HTML response and gives it no independent browser-cache entry; in exchange, it removes a render-blocking round trip. The build checks every page's embedded CSS against `src/assets/site.css`. The original `/assets/site.css` file remains published so previously cached pages that still reference it continue to work. The deferred site script keeps a content-hashed URL so a deployment cannot pair current markup with a stale cached search or ad loader.

Google Analytics initializes and starts loading in the document head on the production host. AdSense starts after the page's `load` event and two animation frames, giving the initial content a chance to paint first. It keeps its existing production publisher ID and asynchronous script behavior. Local and preview hosts do not request these vendor scripts.

The AWS site uses private S3 behind CloudFront origin access control. CloudFront maps clean URLs to generated `index.html` files, redirects extensionless paths to trailing slashes, redirects `www` to the apex, and serves a real 404 page for unknown content. GitHub Actions assumes a narrowly scoped AWS role through OIDC and deploys every push to `main`. The public domain and AWS preview domain use the same distribution. Route 53 serves authoritative DNS for the domain while registration remains at GoDaddy; mail and verification records are preserved in the Route 53 zone.

The homepage includes a compact optional course section for architecture and application development. The static `/certifications/` page groups selected courses by foundations and architecture, application development, cloud operations, and advanced networking. Readers can also reach that page from the shared footer. `src/_data/courses.json` owns selected course names, canonical destinations, instructor attribution, and reusable exam-version qualifications; each surface owns its recommendation reason in front matter. The certifications page also owns the path heading and official AWS exam reference for each selected course, and renders every selected course through one shared loop. Articles may select one or more catalog products in `courseRecommendations` front matter, with an article-specific reason for each. An absent or empty selection adds no article group or disclosure. Otherwise, the shared post layout adds one compact complementary aside after the original body and before the author summary, outside technical contents navigation. Course names, instructor attribution, qualifications, and direct links come from the catalog; recommendation reasons remain plain escaped text. The build validates selected keys and direct HTTPS course URLs, then adds the site's referral code. Each recommendation group shows the affiliate disclosure once and uses `rel="sponsored"`; links open in the current tab. Courses are paid and optional, and do not replace the free article, topic guides, or official AWS exam information. The current Developer course page names DVA-C02 while AWS has announced DVA-C03; the Advanced Networking exam is scheduled for retirement on December 31, 2026. The Security – Specialty and Solutions Architect – Professional catalog entries are article-only selections in the current homepage/certifications setup. The provider's Security curriculum names SCS-C02 while AWS's current exam is SCS-C03, so it is recommended for broader security skills without claiming current SCS-C03 preparation. The Professional course page names SAP-C02; its qualification calls out SAP-C03 registration opening October 27, 2026 and the final SAP-C02 exam date November 16, 2026, and asks exam readers to confirm coverage for their target version.
