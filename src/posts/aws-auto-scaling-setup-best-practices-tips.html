AWS Auto Scaling basics

Key terms and ideas

AWS Auto Scaling helps manage resources for your apps. Here are some key terms:

How AWS Auto Scaling works

AWS Auto Scaling follows these steps:

  1. Monitoring: Tracks app workload using metrics like CPU use or request wait times
  2. Scaling Decision: Chooses whether to add or remove resources based on metrics
  3. Scaling Action: Starts or stops EC2 instances as needed

Main parts of AWS Auto Scaling

AWS Auto Scaling has three main parts:

  1. Auto Scaling Group (ASG)

    • Core part of AWS Auto Scaling
    • A group of EC2 instances that scale together

  2. Launch Template

    • Sets up new EC2 instances for the ASG
    • Replaces older launch configurations

  3. Scaling Policies

    • Decide when to scale the ASG
    • Three types:
      1. Target Tracking Scaling: Aims for a specific metric value
      2. Simple Scaling: Adds or removes instances based on a threshold
      3. Step Scaling: Uses predefined steps to adjust instance count

How to create an Auto Scaling group

To set up an Auto Scaling group:

  1. Go to the AWS Management Console and find the Auto Scaling dashboard
  2. Click "Create Auto Scaling group" and name your group
  3. Pick a launch template for your instances
  4. Choose your VPC and subnets
  5. Set your minimum and maximum instance numbers
  6. Set up your scaling rules
  7. Check everything and create your group

Setting up launch templates

Launch templates tell AWS how to set up new instances. To make one:

  1. Go to the EC2 dashboard and click "Launch Templates"
  2. Click "Create launch template" and give it a name
  3. Pick an Amazon Machine Image (AMI)
  4. Choose your instance type
  5. Set any other options you need
  6. Check everything and create your template

Connecting with Elastic Load Balancing

Elastic Load Balancing spreads traffic across your instances. To connect it to your Auto Scaling group:

  1. In the EC2 dashboard, click "Load Balancers"
  2. Click "Create Load Balancer" and pick a type
  3. Set up your load balancer, including VPC and subnets
  4. Pick the Auto Scaling group to connect
  5. Set any other options you need
  6. Check everything and create your load balancer

Using multiple zones for better uptime

Advanced Auto Scaling methods

Scaling based on future needs

AWS Auto Scaling can adjust resources based on predicted future needs. This uses machine learning to forecast demand and change capacity accordingly.

This works well for apps with changing workloads. It looks at past usage to prepare for future changes, helping avoid having too few or too many resources.

To use this:

  1. Gather data on how your app has been used in the past
  2. Make a predictive scaling policy in AWS Auto Scaling
  3. Set up the policy to change capacity based on what it predicts

Scaling on a set schedule

You can set AWS Auto Scaling to change resources at specific times. This helps when you know when your app will be busy.

For example, if your app gets busy every morning, you can set it to add more resources then.

To do this:

  1. Figure out when your app gets busy
  2. Make a scheduled scaling policy in AWS Auto Scaling
  3. Set the policy to change resources at those times

Scaling to meet specific goals

Step scaling lets you change resources based on specific measures. For example, you can add more resources when CPU use gets high.

This helps you meet exact performance goals.

To use step scaling:

  1. Choose what to measure (like CPU use)
  2. Make a step scaling policy in AWS Auto Scaling
  3. Set the policy to change resources based on your measures

Scaling in steps

Step scaling can also change resources bit by bit, not all at once. This is good when sudden changes might cause problems.

By changing slowly, you can better match what you need without overdoing it.

To set this up:

  1. Decide how much to change each time
  2. Make a step scaling policy in AWS Auto Scaling
  3. Set the policy to change resources in small steps

Using Reserved Instances and Savings Plans

Reserved Instances (RIs) and Savings Plans are two more ways to save money. They both give you a discount if you agree to use AWS for a certain amount of time.

Setting rules to stop unused resources

Another way to save money is to turn off resources you're not using. You can do this by setting up rules in AWS.

For example, you can make a rule that turns off EC2 instances when they're not busy. This way, you only pay for what you use.

Here's how to set up a rule to turn off unused instances:

  1. Use CloudWatch to check how busy your instances are
  2. Make a rule that turns off instances when they're not busy
  3. Use Auto Scaling to turn instances on and off based on the rule

This can help you save a lot of money by not paying for resources you don't need.

Fixing common Auto Scaling problems

Finding out why scaling isn't working

When Auto Scaling doesn't work as expected, follow these steps to find the problem:

  1. Check the Auto Scaling group setup
  2. Look at CloudWatch metrics and alarms
  3. Review the Auto Scaling group's activity history

Dealing with capacity issues

Capacity problems can happen when:

  • Desired capacity is outside min/max limits
  • Scaling doesn't happen as expected

To fix these issues:

  1. Change desired capacity to fit within limits
  2. Adjust min/max limits if needed
  3. Check scaling rules and CloudWatch settings

Fixing unhealthy instances

Unhealthy instances can stop Auto Scaling from working right. Here's how to fix them:

  1. Find the cause by checking logs and metrics
  2. Fix the problem (restart, update, or replace the instance)
  3. Make sure the instance is working after fixing it

Watching and understanding Auto Scaling

Using CloudWatch to track and alert

CloudWatch helps you keep an eye on your Auto Scaling. It can tell you when something needs your attention.

To set up CloudWatch alerts for Auto Scaling:

  1. Go to the CloudWatch console
  2. Click "Alarms" on the left
  3. Click "Create Alarm" and pick "Auto Scaling"
  4. Choose your Auto Scaling group and what to watch (like CPU use)
  5. Set when to alert you

This helps you know when to check on your app.

FAQs

How to configure Auto Scaling?

Setting up Auto Scaling in AWS involves these steps:

1. Log into AWS

  • Go to the AWS Management Console
  • New users may get free EC2 use (with limits)

2. Make a Launch Template

  • Go to EC2 Console > Launch Templates
  • Set up:
    • Template name
    • Amazon Machine Image (AMI)
    • Instance types
    • Security group (virtual firewall)

3. Set up Auto Scaling Group (ASG)

  • Use the Auto Scaling wizard
  • Choose:
    • ASG name
    • Size
    • Network

4. Add Load Balancer (if needed)

  • Helps spread out traffic
  • Set up Elastic Load Balancing (ELB)
  • Connect ELB to your ASG

5. Set Scaling Rules (if needed)

  • Decide when to add or remove instances
