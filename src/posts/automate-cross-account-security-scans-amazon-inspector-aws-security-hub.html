Automating security scans across multiple AWS accounts is crucial for efficiency, consistency, and comprehensive coverage. This guide shows you how to:

  • Set up and configure Amazon Inspector and AWS Security Hub
  • Automate security scans
  • Review findings
  • Remediate vulnerabilities across accounts

Prerequisites

AWS Accounts and Access

To automate cross-account security scans, you need:

  • An AWS administrator account with permissions to set up and configure Amazon Inspector and AWS Security Hub
  • Multiple AWS accounts you want to monitor and scan for security vulnerabilities
  • AWS IAM roles or users with permissions to access and manage the required AWS services

Agents or Components

Current Amazon Inspector uses the Systems Manager (SSM) Agent for agent-based EC2 package scanning and EBS snapshots for agentless scanning. Review the EC2 scanning prerequisites for your instances and scan mode. Security Hub CSPM receives findings through service integrations without a separate Security Hub agent.

This guide refers to current Amazon Inspector. Inspector Classic, which used assessment targets and a separate agent, reached full shutdown on May 20, 2026; see the AWS lifecycle registry.

Step 1: Set up Amazon Inspector

Designate an Administrator Account

To get started with Amazon Inspector, you'll need to designate an administrator account. This account will manage Amazon Inspector for your organization:

  1. Log in to your AWS Organizations management account.
  2. Open the Amazon Inspector console at https://console.aws.amazon.com/inspector/v2/home.
  3. In the Delegated administrator pane, enter the 12-digit ID of the AWS account you want to designate as the Amazon Inspector administrator. Then choose Delegate and confirm.

Configure Scan Types

Next, you'll need to configure the scan types you want to enable. Amazon Inspector offers three scan types: EC2, ECR, and Lambda. You can enable one, two, or all three based on your needs.

To configure scan types:

  1. Log in to the designated administrator account.
  2. Open the Amazon Inspector console.
  3. In the navigation pane, choose Account Management.
  4. Select the accounts you want to enable scanning for.
  5. Choose the scan types to enable (EC2, ECR, or Lambda).

Example: EC2 Scan Configuration

In the delegated administrator account, use Account management to activate EC2 scanning for the member accounts you intend to monitor in each relevant Region. Follow the AWS multi-account guide for account enrollment and automatic activation for new members.

For agent-based package scanning, verify that the supported EC2 instances are managed by Systems Manager and have the required permissions. Review scan coverage to identify excluded or unscanned instances. Current Inspector performs scanning after activation; assessment targets and manually scheduled Classic assessment runs are not part of this workflow.

Step 2: Set Up AWS Security Hub

Enable AWS Security Hub

To enable AWS Security Hub:

  1. Open the AWS Security Hub console at https://console.aws.amazon.com/securityhub/.
  2. Choose the Region where you want to enable Security Hub.
  3. Choose Go to Security Hub CSPM when onboarding, then choose Enable Security Hub for manual setup.
  4. Review the terms and conditions, then click Enable Security Hub to confirm.

For console, AWS CLI, and API setup, follow AWS's Security Hub CSPM enablement guide. For an organization, designate its delegated administrator and configure member enrollment in the relevant Regions.

Integrate with Amazon Inspector

Enable Amazon Inspector and Security Hub CSPM in the accounts and Regions you intend to monitor. Enabling Security Hub CSPM automatically activates its Inspector integration, which sends Inspector findings in AWS Security Finding Format (ASFF). Follow the official integration guide to review configuration and filtering. This integration does not include Amazon Inspector Code Security findings.

For cross-account visibility, configure Security Hub CSPM's own organization administration and member enrollment as well as Inspector's delegated administration. The two services have separate account-management settings.

Verify the Integration

To verify that Amazon Inspector findings are being sent to AWS Security Hub:

  1. Open the AWS Security Hub console at https://console.aws.amazon.com/securityhub/.
  2. Choose the Region where you enabled Security Hub.
  3. Click Findings in the navigation pane.
  4. Look for findings from Amazon Inspector. If you don't see any findings, check that the integration is set up correctly and that Amazon Inspector is sending findings to Security Hub.

Step 3: Verify Continuous Scanning and Coverage

Current Amazon Inspector automatically scans supported resources after their scan types are activated. EC2 scan cadence depends on the scan method; use AWS's EC2 scanning documentation to understand the behavior for your environment.

Review Scanning Coverage

  • Review scanning status and coverage for the intended member accounts and Regions.
  • Check that supported instances are enrolled and that exclusions are intentional.
  • Monitor new and updated findings, and resolve coverage gaps before relying on the results.

Route Finding Events with EventBridge

Use EventBridge to route finding events to notification or remediation workflows; see Amazon Inspector with EventBridge. These workflows handle findings rather than schedule retired Classic assessment targets.

Use Systems Manager Automation for Remediation

Systems Manager Automation can run approved remediation actions when a finding workflow calls for them. It is not required to schedule current Inspector's continuous scanning.

Step 4: Review Findings

Access Findings in AWS Security Hub

Now that you've set up Amazon Inspector and integrated it with AWS Security Hub, you can review the findings:

  1. Log in to the AWS Security Hub console.
  2. In the navigation pane, choose Findings.
  3. Select the findings you want to review. You can filter by severity, resource type, and other criteria.

Prioritize and Analyze Findings

When reviewing findings, focus on those with high severity and impact. Analyze the findings to understand the issue and identify affected resources. Here's how to prioritize and analyze findings:

  • Severity: Focus on Critical or High severity findings.
  • Resource type: Prioritize findings related to critical resources like EC2 instances or S3 buckets.
  • Compliance: Identify findings relevant to specific compliance standards or security frameworks.

Use Filters and Custom Insights

AWS Security Hub provides filters and custom insights to help you focus on critical findings. You can create custom insights to group related findings and identify trends.

To create a custom insight:

  1. In the AWS Security Hub console, choose Insights.
  2. Click Create insight.
  3. Select the relevant findings and filters to include.
  4. Choose a name and description for the insight.
  5. Click Create insight.

Step 5: Fix Security Vulnerabilities (Optional)

Use AWS Systems Manager Automation

To fix security vulnerabilities across multiple resources, you can automate the process using AWS Systems Manager Automation. This service lets you create an Automation runbook that targets specific resources, like Amazon EC2 instances, based on tags or resource IDs.

Here's how to fix Amazon Inspector findings with AWS Systems Manager Automation:

  1. Create an Automation runbook targeting the affected resources.
  2. Specify the fix action, such as patching or updating software.
  3. Configure the runbook to reboot instances after fixing, if needed.
  4. Run the runbook to fix the vulnerabilities.

Integrate Third-Party Tools

You can also integrate third-party vulnerability management tools with AWS to automate fixing vulnerabilities. For example:

  • Use a tool like Nessus, Qualys, or OpenVAS to identify vulnerabilities.
  • Then, use AWS Systems Manager Automation to fix them.
